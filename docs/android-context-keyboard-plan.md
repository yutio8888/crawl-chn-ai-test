# Android 情境键盘实施说明

仅在当前 `codex/android-context-keyboard` worktree 实施和提交，不 push、merge
或修改其他分支。基线为 `6b82440c54`。

## 接口与布局

保留 `ui::InputContext` 的 GAME=0、NAVIGATION=1、TEXT=2。Android 专用
描述符追加界面类型及六个固定动作槽；动作拥有翻译后的 `std::string`
标签和游戏输入键值。已有原生标签用 `T_()`；翻译表中没有的新键盘短标签
由 Java 按界面和槽位取 Android strings/values-zh 资源，原生标签留空、
非零键值表示动作存在。槽 0 为确认/是/继续，槽 1 为取消/否/返回，槽 2–5
为其他动作；空槽不发送输入。仿照 `TextInputScope`，用 RAII 保存、登记、
恢复描述符，并避免底层界面的动作泄漏到嵌套界面或文本输入。

扩展现有 `jni_input_context` 通道，C++ 比较完整描述符后才调用 JNI。
Activity 重建完成新键盘后以原子标志请求重发，并唤醒原生事件等待；
去重缓存仍仅由原生线程访问，重发后恢复正常去重。
Java 在 UI 线程更新标签和六个固定按钮，空槽使用 INVISIBLE。字符与
常规控制键沿用 InputConnection；仅实际需要的 CK_* 键通过 SDL 事件队列
传递，不从 Java UI 线程直接操作游戏状态。

紧凑布局补齐为四行，与完整布局共用固定的四行高度。上下文或手动布局
切换不改变键盘占用高度；显示/隐藏仍使用现有 Surface resize 通道。
48dp 最小按键高度仅用于 option 4；Classic option 1/2 保留已保存尺寸。
固定四行只要求各布局使用同一实际行高，不要求提高 Classic 的行高。
手动选择完整键盘后自动上下文不得覆盖，手动返回紧凑键盘解除该选择。
布局与上下文切换用 `Log.i("AndroidKeyboard", ...)` 留下诊断日志。

## 覆盖范围

- 分页背包、丢弃、拾取、已知物品：按实际分页与菜单 flags 提供类别切换、
  多选全选、动作切换和确认。
- 物品及法术描述：从实际可用操作生成按钮，并提供返回。
- 瞄准：确认、取消、前后目标、自身。
- 是非提示与 more：是/否、继续。
- 关卡地图：楼梯及传送点/特征循环、返回；主地牢保留现有动作。

## 验收与非目标

按“C++ 描述符与作用域”“Java 槽位与固定高度”“各界面接入”独立提交。
验证嵌套界面退出恢复、按钮与真实键盘行为一致、空槽不可点击、手动完整
布局保留、紧凑/完整及上下文切换时 Surface 尺寸不变。运行隔离包装的
`verify_zh.sh --profile code`，尝试构建 x86_64 Android debug APK 并在可用
模拟器冒烟；完整记录环境限制和未验证项。

非目标：桌面 tiles 行为、翻译资产、地形抽屉命令、持久偏好、新目录、
通用反射机制及其他界面扩展。新增 C++ 功能均受 `__ANDROID__` 保护；
新增文案使用 `T_()` 或 Android 字符串资源，不修改 `dat/i18n/zh/`。
