# 玩家种族与背景全量校对计划

本计划对应 GitHub Issue #26。目标是从当前生产源冻结完整、唯一且带生命周期的
玩家种族与背景清单，对每个身份给出一张证据卡和一个终态结论，并只修改中文
显示资产、术语文档与审计工具，不改游戏平衡或协议身份。

## 验收边界

- 种族身份以活动的 `species-type-header.txt` 与 `dat/species/*.yaml` 交叉验证；
  背景身份以活动的 `job-type-header.txt`、`dat/jobs/*.yaml` 和兼容背景模板交叉验证。
- Wiki 首页只用于确认“种族/背景”实体分类，不作为生产数量或生命周期权威。
- 每个种族核对名称、缩写、形容词/属名、体形和装备限制、基础属性、
  XP/HP/MP/意志修正、完整适性表、等级特性、变异/能力事实与描述。
- 每个背景核对名称、缩写、基础属性、起始技能、装备、法术、信仰事实与描述。
- 物品、ego 和法术名称复用已完成审计的现行结论；本计划只检查引用一致性。
- 种族附带的能力/变异只记录生产事实，身份级翻译结论仍归 Issue #27。
- 兼容身份进入同一清单并给出终态结论，但不虚构现役选择界面描述或起始配置。

## 冻结方法

```bash
python3 .claude/scripts/audit_species_background_inventory.py \
  --output /tmp/species-background-inventory.json
```

脚本使用现有 SourceDB 物理键解析器和 TAG 分支解析器，记录基线提交、术语表
SHA-256、每个输入文件 SHA-256、逐项生产数据、描述和中文显示形式。以下任何
情况均非零退出：

- 枚举与数据身份集合不相等、重复或出现意外身份；
- 中文名称或生产所需形容词/属名缺失；
- 现役身份缺少英文或中文描述；
- 描述键重复，或中文描述含有生产清单外的陈旧键。

## 批次与所有权

同一 `zh-translator` 顺序写入全部 ZH 资产，不允许并发写者：

1. 冻结生产清单并记录初始结构发现；
2. 校对现役种族、龙人变体和兼容种族；
3. 校对现役背景和兼容背景；
4. 更新术语表并重新解析术语上下文；
5. 由 `crawl-coder` 接入只读 inventory 与负向测试；
6. 运行 translation/code/ci 中与最终 diff 匹配的开发验证；
7. 准备干净候选，按机械路由完成翻译和代码审查，再运行最终门禁。
