## 4. 为什么需要完整复审

1. 历史名称审计、身份完整性检查和文本存在性检查不证明正文语义正确。
2. 现有 god inventory 保存描述键集合，但不逐段绑定正文；角色机制 inventory 也不覆盖所有形态伪变异和全部独立状态描述。本轮对这些正文的改动，不能只靠对应 inventory 的绿色结果证明完成。
3. 名称一致也可能共同出错；术语表是项目约定，不是独立正确性证明。
4. 单个名称、长描述、动态短消息和实际显示属于不同证据层，必须在各层各自证明覆盖，再核对它们的对应关系。
5. 小样本和实测能发现问题，不能给未出现的内容自动签发 `keep`。

## 7. 每条证据和审查职责

沿用各域现有证据卡格式；至少记录 identity、完整源文与当前译文的定位/摘要、显示语境、结论、原因、建议及证据引用。新增正文覆盖时补在对应域结果中，不另建同义账本。

- `keep` 必须说明已核对哪些关键命题，不能由哈希相同、通过静态检查或历史结论自动推导。
- `adjust` / `retranslate` 记录错误影响及采用译文。相同根因只解释一次，并列出受影响成员。
- `defer terminology` / `defer implementation` 必须有保留的当前值、缺少的证据、负责角色和重新进入的触发条件；“证据不足”本身不是无条件完成。
- 名称规范与语义正确性分别记录。合理同义表达、字序变化和个人文风偏好不自动升级为必改项。
- 英文与实现冲突时分别记录上游问题和本地译文问题，不悄悄改写英文事实；当前正确的协议/存档身份也不随显示名称翻译。

职责使用 `docs/agent-routing.md` 的当前角色配置：翻译审校负责语义与术语，代码审校负责格式/边界/运行行为；译者是中文资产唯一写入者，代码作者负责实现。审查者只读，修改返回资产所有者。是否并行和使用何种模型在执行时按授权与当前配置决定，不在计划中固化模型名单。

独立审校输入应给源文、译文、上下文和原始机制证据；先形成意见，再查看其他审校结论。不能把本轮两份报告当作自动裁决器，也不能把未做独立复查的自查称作独立审查。
